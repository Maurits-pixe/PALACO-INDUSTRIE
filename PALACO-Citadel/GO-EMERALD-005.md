# GO-EMERALD-005 — SCHEMA & GENERATION SPECIFICATION

## Scope

GO-EMERALD-005 moves Emerald Imperium from conceptual protocol to machine-readable specification and generation structure.

## Canonical object law

- ONE CANONICAL MINERAL SPECIES → ONE UNIQUE EMERALD WORLD
- MINERAL WORLD ≠ WORLD SLOT
- WORLD ID is immutable across rename/redefine/discredit/revalidate events.

## Source and allocation separation

- SOURCE_SET: complete IMA-CNMNC source records.
- CANONICAL_SET: validated records eligible for world identity mapping.
- WORLD_ALLOCATION_4444: bounded allocation surface for 4444 Other Worlds.

## Allocation state machine

DISCOVERED → INGESTED → NORMALIZED → IDENTITY-VALIDATED → ALPHABETICALLY-ORDERED → WORLD-ASSIGNED → WATERMARKED → HOLOGRAMMED → CITADEL-BOUND → IMMORTALIZED

Allocator fail-closed on collisions, ambiguity, duplicates, invalid status, or missing provenance.

## Identity and status separation

- STATUS ≠ IDENTITY.
- Name changes update lineage under the same world ID.
- Historical states are preserved and never silently deleted.

## Constitutional boundary

Registry objects may identify, describe, relate, and provide context; they may not authorize, govern, or grant sovereignty.
